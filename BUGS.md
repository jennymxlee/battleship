# Battleship: debugging notes

Testing combined pure-rule tests, React component tests, seeded AI simulations, automated review, and an independent Chromium bug bash at desktop and 360px touch sizes. The issues below were actually found during development; they were not invented for this document.

## Bugs found and fixed

| Problem / how it was found | Root cause and fix | Regression coverage |
| --- | --- | --- |

Occupied-cell clicks now only select; a completed/randomized fleet has no active selection. Dragging still allows overlapping moves along a ship's own line. [Fix](https://github.com/jennymxlee/battleship/commit/1418573). | [`BugBash.test.tsx`](src/components/BugBash.test.tsx): selection does not move ships; stray clicks preserve completed fleets. |

The eight new bug-bash regression cases were run against the original implementation first: **all eight failed**, then passed with the fixes. A keyboard test also timed out because `user-event` was used with fake timers; that was a test-harness problem, fixed by using real timers, not a game defect.

## What was checked, and limits

- Rules/tests cover out-of-bounds and overlapping placements, touching ships sinking independently, repeat shots, alternating turns, and win detection. StrictMode and fake-timer tests cover exactly one AI reply, restarting mid-turn, and unmount cleanup.
- Verification: **82 unit/component tests** and **6 full-game Playwright tests** pass, with lint, typecheck and production build. Playwright plays every difficulty at desktop and 360px touch sizes, checks exactly one AI shot per turn, inspects the final boards, then starts again. These browser tests also run in CI.
- The independent bug bash completed wins and losses at every difficulty and found no console errors, repeated AI shots, or horizontal overflow at 360px. Mouse/touch dragging and keyboard firing worked.
- `npm run sim` compares 200 identical seeded fleets per difficulty: mean shots to win **95.2 / 49.5 / 45.5** for Easy / Medium / Hard. Hard is a heuristic, not an optimal solver: it can be worse than Medium on tightly packed fleets or individual games.
- Real screen readers, Safari/iOS, and Firefox have not been verified. A 10×10 board has small touch targets on narrow phones; browser zoom remains available. Touching ships share a fill colour, but cells identify each ship in their accessible labels.
- **Release prerequisite:** GitHub Pages must be enabled (Source: GitHub Actions), and the game PRs merged. The bug bash found the public URL returning 404 because Pages was not enabled; this is a deployment blocker, not a gameplay fix.

Dependency audit also found vulnerable development tooling in the initial scaffold. Vitest was upgraded to a patched release, the simulator's `vite-node` dependency made explicit, and ESLint's transitive `minimatch` constrained to a patched version. `npm audit` now reports **0 vulnerabilities**; lint, unit tests and E2E were rerun after these changes.
